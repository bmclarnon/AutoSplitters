# Contributing

Thank you for considering to contribute to this repository. We outline a few
steps to land your contribution below.

## Generative AI Policy

Contributions implemented, generated, or refactored by AI models (e.g., GitHub
Copilot, ChatGPT, Claude) will not be accepted.

We maintain a strict human-only contribution policy for the following reasons:

- **Review Balance:** AI-driven contributions can create a dangerous imbalance
  where maintainers spend more time auditing and fixing code than the
  contributor invested in generating it.
- **Authenticity:** There is minimal project value in having an external
  contributor act as a non-expert intermediary between a maintainer and an AI
  model.
- **Code Provenance:** We must guarantee the legal licensing, safety, and source
  origin of all incoming code.

PRs suspected of being fully or partially generated by AI may be closed without
a detailed review. Repeated violations will result in being blocked from the
repository.

Incidental use of autocomplete is not a violation of this policy, but
contributors are expected to understand, review, and stand behind the contents
of their PRs.

## Testing

Until this repo does not yet have good automated tests, changes should be
manually tested using [asr-debugger](https://github.com/LiveSplit/asr-debugger).

## Submitting changes

PRs should be accomanied by a description of what is being changed and why,
following the [Conventional Commits](https://www.conventionalcommits.org/)
specification. Document any manual testing that was performed. If a PR is
composed of multiple commits, use a squash merge.

Each PR should be small and single-purpose, while still leaving the codebase in
a functional state. If an issue will require multiple PRs that don't stand
alone, create an Issue to document the design and track progress.

All PRs must pass all automated tests and lint checks.

## Coding conventions

- Code should prioritize readability and maintainability over writability.
- Files must pass the appropriate lint checks. markdownlint and rust-analyzer
  run automatically on PRs.
- Cargo code must pass clippy checks, which are run automatically on PRs.
- New code should be tested. See [Testing](#testing).
- Every non-obvious struct, function, and member variable should have a comment
  that describes what it is for and how it should be used. This includes private
  symbols.
